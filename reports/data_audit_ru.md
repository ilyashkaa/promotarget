# Анализ данных Online Retail II

## 1. Описание проекта

**PromoTarget** — ML-проект, направленный на прогнозирование повторных покупок клиентов интернет-магазина и формирование целевой аудитории для маркетинговых кампаний.

Основная задача — определить вероятность того, что существующий клиент совершит хотя бы одну повторную покупку в течение следующих 30 дней.

Для исследования используется датасет **UCI Online Retail II**, содержащий историю транзакций британского интернет-магазина за период с декабря 2009 по декабрь 2011 года.

На данном этапе выполнены первичный аудит данных, исследование аномальных транзакций, проверка дублирования между периодами и анализ поведения покупателей.

## 2. Первичный аудит данных

Исходный датасет состоит из двух листов Excel:

| Период | Количество строк |
|---|---:|
| 2009–2010 | 525 461 |
| 2010–2011 | 541 910 |
| **Всего** | **1 067 371** |

Каждая строка представляет товарную или служебную позицию в рамках транзакции, а не отдельный заказ.

Датасет содержит восемь столбцов: `Invoice`, `StockCode`, `Description`, `Quantity`, `InvoiceDate`, `Price`, `Customer ID`, `Country`.

Схемы обоих листов совпадают.

### Анализ пропусков

Наиболее существенная проблема — отсутствие `Customer ID`.

| Столбец | 2009–2010 | 2010–2011 |
|---|---:|---:|
| Customer ID | 20,54% | 24,93% |
| Description | 0,56% | 0,27% |

Всего обнаружено 243 007 строк без идентификатора клиента, или около 22,77% исходных записей.

Отсутствие `Customer ID` не позволяет однозначно связать транзакцию с конкретным покупателем. Поэтому такие записи не будут использоваться при построении клиентской ML-выборки.

Пропуски в `Description` не являются критичными для базового определения покупки, поскольку для этого достаточно идентификатора клиента, номера заказа, даты, количества, цены и типа позиции.

## 3. Анализ качества транзакций

В результате исследования выявлены следующие особенности данных:

| Категория | Количество строк |
|---|---:|
| Отрицательное количество товара | 22 950 |
| Нулевая цена | 6 202 |
| Отрицательная цена | 5 |
| Строки с отменёнными Invoice | 19 494 |
| Полные дубликаты внутри листов | 12 133 |

Категории могут пересекаться. Приведённые значения рассчитаны до устранения межлистового дублирования.

### Отрицательные количества

Обнаружено 3 457 строк с отрицательным `Quantity`, у которых `Invoice` не начинается с `C`.

Среди описаний встречаются `lost`, `damages`, `short` и другие обозначения, характерные для складских корректировок.

Это показывает, что проверка только префикса `C` недостаточна для определения валидной покупки.

### Нулевые и отрицательные цены

Среди строк с положительным количеством обнаружено 2 745 записей с нулевой ценой.

Часть из них имеет известный `Customer ID` и обычный товарный артикул. Такие операции могут быть бесплатными товарами, подарками или ошибками учёта. Их точная природа не установлена.

Все пять записей с отрицательной ценой имеют `StockCode = B` и описание `Adjust bad debt`. Они относятся к бухгалтерским корректировкам, а не обычным товарным покупкам.

## 4. Анализ служебных операций

В датасете обнаружены специальные коды, не обозначающие обычные товары.

| StockCode | Значение |
|---|---|
| POST | Почтовые расходы |
| DOT | Расходы на доставку интернет-заказов |
| M | Ручная операция |
| D | Скидка |
| B | Корректировка задолженности |
| BANK CHARGES | Банковские комиссии |

Для базовой версии PromoTarget решено исключить эти позиции при определении товарной покупки.

При этом наличие служебной позиции внутри заказа не делает весь заказ невалидным. Если в одном Invoice есть хотя бы одна валидная товарная позиция, заказ может учитываться как покупка.

## 5. Межлистовое дублирование

Временные диапазоны двух листов пересекаются в декабре 2010 года.

В ходе проверки обнаружено:

- 1 088 номеров Invoice, присутствующих в обоих листах.
- 22 523 строки, относящиеся к этим Invoice, в каждом листе.
- 22 202 уникальные полностью совпадающие записи.
- Отсутствие различий между пересекающимися наборами записей при сравнении частот одинаковых строк.

Таким образом, подтверждено межлистовое дублирование транзакций.

Для объединения периодов выбрана стратегия сохранения всех строк первого листа и исключения из второго листа Invoice, уже присутствующих в первом.

Это позволяет устранить подтверждённые межлистовые дубликаты, не удаляя автоматически одинаковые товарные позиции внутри отдельных листов.

После объединения получено **1 044 848 строк**.

## 6. Определение валидной товарной покупки

Для MVP принято следующее рабочее определение валидной товарной позиции:

- Указан `Customer ID`.
- `Quantity > 0`.
- `Price > 0`.
- `Invoice` не начинается с `C`.
- `StockCode` не принадлежит установленному списку служебных кодов.

После применения этих условий осталось **788 499 строк**, или 75,47% объединённого датасета.

Это рабочее определение платной товарной покупки. Оно не учитывает полное влияние возвратов и скидок на чистую выручку.

Для определения факта покупки будем использовать наличие хотя бы одной валидной товарной позиции внутри заказа.

## 7. Анализ повторных покупок

После подготовки данных были рассчитаны основные показатели покупательской активности.

| Показатель | Значение |
|---|---:|
| Уникальных покупателей | 5 862 |
| Уникальных заказов | 36 645 |
| Покупательских дней | 32 914 |
| Клиентов с покупками минимум в два разных дня | 4 181 |
| Доля таких клиентов | 71,32% |

Для анализа повторных покупок введено понятие **покупательского дня** — календарной даты, в которую клиент совершил хотя бы одну валидную покупку.

Несколько заказов одного клиента в течение дня считаются отдельными Invoice, но одним покупательским днём.

### Интервалы между покупками

Было рассчитано 27 052 интервала между последовательными покупательскими днями.

| Статистика | Значение |
|---|---:|
| Средний интервал | 59,27 дня |
| Медианный интервал | 32 дня |
| Первый квартиль | 13 дней |
| Третий квартиль | 70 дней |
| Максимальный интервал | 714 дней |

Среднее значение значительно превышает медиану, что указывает на правостороннюю асимметрию распределения.

### Доля интервалов в зависимости от горизонта

| Горизонт | Доля интервалов |
|---|---:|
| 7 дней | 15,76% |
| 14 дней | 28,63% |
| 30 дней | 49,07% |
| 60 дней | 70,86% |
| 90 дней | 80,61% |

Почти половина наблюдаемых интервалов между последовательными покупательскими днями не превышает 30 дней.

Однако эти значения рассчитаны только для наблюдаемых повторных покупок и не учитывают клиентов, чья следующая покупка отсутствует в периоде наблюдения.

Поэтому приведённые доли нельзя интерпретировать как вероятность повторной покупки для произвольного клиента.

## 8. Предварительная постановка ML-задачи

На основании результатов исследования выбран первоначальный горизонт прогнозирования — **30 дней**.

Задача формулируется следующим образом:

> Для существующего клиента на определённую дату спрогнозировать вероятность совершения хотя бы одной валидной товарной покупки в течение следующих 30 дней.

Объектом ML-выборки будет пара «клиент — дата прогнозирования».

Признаки будут рассчитываться исключительно на основании истории, доступной до соответствующей даты.

Целевая переменная:

- `target = 1` — клиент совершил хотя бы одну валидную покупку в будущем 30-дневном окне.
- `target = 0` — клиент не совершил валидных покупок в полностью наблюдаемом будущем 30-дневном окне.

Клиенты без предшествующей истории покупок не будут включаться в соответствующий временной срез.

Окончательная пригодность горизонта 30 дней будет проверена после построения временной ML-витрины и оценки распределения классов.
